## 3. Требования к компонентам системы

### Компонент 1. Модуль авторизации 

#### 1.1. Границы ответственности
* **Frontend:** Отображение Splash-скрина, проверка наличия локального токена, формы ввода email и 6-значного OTP-кода, таймер блокировки повторной отправки (60 сек), прикрепление токена ко всем запросам.
* **Backend:** Генерация 6-значного кода, публикация события отправки письма в Kafka, валидация кода и количества попыток, выпуск токена сессии со сроком жизни ровно 30 дней.


#### 1.2. Функциональные требования
* **Splash-скрин и роутинг:** При открытии приложения отображается сплэш-скрин. Если в локальном хранилище есть валидный токен, происходит редирект на главный экран обучения (0 кликов до контента). Если токена нет или сервер вернул `401 Unauthorized` - редирект на экран ввода почты.
* **Запрос кода:** Экран содержит поле `Email`  и кнопку «Войти». При отправке запроса создается запись в `auth_codes`, а в топик Kafka публикуется задача на отправку 6 цифр пользователю.
* **Ввод OTP-кода:** Экран содержит 6 ячеек ввода. Отправка запроса на сервер происходит по нажатию кнопки «Отправить код».
* **Повторная отправка кода:** Кнопка «Отправить код повторно» неактивна первые 60 секунд после рендера экрана (отображается обратный отсчет). При нажатии старый код инвалидируется, генерируется новый.
* **30-дневная сессия:** При успешной проверке кода сервер создает пользователя в `users` (если он входит впервые, назначая ему словарь по умолчанию) и возвращает токен со сроком жизни 30 суток. Каждые 30 дней требуется повторная авторизация.


#### 1.3. Обработка исключений
* **Брутфорс кода:** Если пользователь ввел неверный код 3 раза подряд, текущий код аннулируется, пользователю предлагается запросить новый код.
* **Истечение токена во время сессии:** Если 30 дней истекли в момент сессии, клиент перехватывает `401`, сохраняет несинхронизированный ответ в локальное хранилище, переводит на экран входа, а после успешного входа досылает сохраненный ответ.




### Компонент 2. Словарь

#### 2.1. Границы ответственности
* **Frontend:** Отображение списка доступных словарей в настройках, скачивание состава выбранного словаря в клиентский стейт, проверка версии словаря (`version`) для подгрузки обновлений, сброс прогресса.
* **Admin Panel:** Парсинг `.xls / .xlsx` файлов через, валидация строк, табличное редактирование и экспорт обратно в `.xlsx`.
* **Backend:** Хранение словарей и слов, транзакционное сохранение импорта, мягкое удаление слов (`is_deleted = true`).

#### 2.2. Функциональные требования

##### 2.2.1. Клиентское веб-приложение 
* **Словарь по умолчанию:** При первом входе пользователя в систему (после авторизации) ему автоматически назначается словарь с флагом `is_default = true`. Экран предварительного просмотра слов не предусмотрен — пользователь сразу видит первую карточку из словаря по умолчанию.
* **Список словарей в настройках:** В разделе «Настройки» пользователь видит список доступных словарей. Для каждого элемента списка выводятся: название, общее количество слов (`words_count`) и индикатор выбранного словаря.
* **Смена и скачивание словаря:** При выборе другого словаря клиент запрашивает его данные с сервера, сохраняет список слов локально и переключает очередь ротации и экран статистики на выбранный `vocabulary_id`. Прогресс по предыдущему словарю сохраняется на бэкенде и не сбрасывается.
* **Синхронизация обновлений словаря:** При каждом запуске приложения клиент сверяет локальную версию активного словаря (`version`) с серверной. Если на сервере `version` выше, клиент докачивает обновленный состав словаря без потери текущего прогресса по словам.
* **Сброс прогресса:** В настройках пользователь может сбросить свой прогресс:
  * По текущему выбранному словарю (обнуляются счетчики в `Statistics` и удаляются записи о текущих этапах ротации для связки `user_id + vocabulary_id`).
  * По всем словарям сразу.

##### 2.2.2. Административная панель 
* **Импорт словаря из Excel:** 
  * Модератор загружает файл `.xls` / `.xlsx`, указывает название словаря.
  * Фронтенд админки парсит таблицу со столбцами: `Слово (EN)`, `Перевод (RU)`, `Транскрипция`, `Часть речи`.
  * После успешной проверки  данные отправляются единым JSON-массивом на бэкенд.
* **Редактирование словаря:** Модератор может изменить название словаря, исправить опечатки в словах, добавить новые слова или пометить существующие как удаленные. Каждое сохранение изменений увеличивает `version` словаря на +1.
* **Экспорт словаря в Excel:** По нажатию кнопки «Выгрузить» фронтенд админки запрашивает актуальный массив слов словаря и формирует файл `.xlsx`.

#### 2.3. Обработка исключений

| Сценарий | Ожидаемое поведение системы |
| :--- | :--- |
|**Удаление слова, которое уже учит пользователь:** Модератор удаляет слово из словаря в админке, но у пользователя оно находится на n-м этапе ротации или уже выучено. | Физическое удаление (`DELETE FROM words`) запрещено. Выставляется флаг `is_deleted = true`. Слово мгновенно исключается из очереди будущих показов ротации, но если оно уже было в статусе `memorized`, исторический счетчик выученных слов по дням не уменьшается. Пересчитывается `words_count` словаря. |
| **Невалидные данные в Excel при импорте:** В строке 45 пропущена транскрипция, а в строке 82 указана часть речи «Предлог» (отсутствует в `Enum`). | Словарь не создается. Система возвращает ошибку с описанием ошибки. |
| **Дубликаты слов внутри одного Excel-файла:** В загружаемом файле дважды встретилось слово `run` как `Глагол`. | Валидатор отсекает полные дубликаты (одинаковое слово в одном регистре + одинаковая часть речи). При этом омонимы с разной частью речи (например, `run` как `Глагол` и `run` как `Существительное`) считаются разными карточками и успешно сохраняются. |
| **Архивация словаря, который сейчас выбран у пользователя как активный:** Модератор скрыл словарь (`is_archived = true`). | Пользователи, которые уже начали учить этот словарь, могут продолжить его изучение до конца, либо переключиться на другой в настройках. Для новых пользователей архивный словарь в списке выбора не отображается. Нельзя архивировать словарь, если у него стоит `is_default = true` (сначала нужно назначить другой словарь по умолчанию). |
|**В словаре закончились все слова:** Пользователь выучил или пометил как «Уже знаю» 100% слов активного словаря, и очередь ротации пуста. | На главном экране вместо карточки слова отображается заглушка: *«Поздравляем! Вы прошли все слова в этом словаре»* и две кнопки: «Выбрать другой словарь» (редирект в настройки) и «Повторить сейчас» (если в ротации еще остались слова, чей таймер не наступил). |
